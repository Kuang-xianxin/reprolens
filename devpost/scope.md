# ReproLens scope

## Who it is for
A student or independent developer receives a short bug description, logs and later corrections. The intended job is to assemble a shareable issue while preserving the evidence. This audience and demand are hypotheses; no interview or time-saving study has been conducted.

## Core loop and finish
Capture → optional rules/local AI → compare report fields with original text → edit → save → review content/privacy → confirm version → preview/export Markdown. Success is an editable issue with environment, ordered steps, actual and expected results, visible missing sections and optional exact excerpts. Source lookup changes immediately when the reviewer changes wording. History can restore an old version into a new draft.

## Included and cut
One local user, source limits, revisions/conflicts, persistent AI jobs, bilingual responsive UI, cited-excerpt export, recovery and a controlled executed CSV example. No public/team deployment, repository scan, automatic reproduction, diagnosis, issue posting or production-impact claim.

## Acceptance and planning
Mechanical behavior, model quality and user value are assessed separately. Source matches do not prove correct classification. Current bounded evidence and unresolved semantic failures: ../docs/EVALUATION.md. Product requirements flow into prd.md, implementation in spec.md and checks in checklist.md.
