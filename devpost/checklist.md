# Build and submission checklist

## Implemented slices
- [x] Capture selected sources into a local case and preserve original text.
- [x] Edit four report sections, save revisions, restore into a new draft.
- [x] Optional real local AI with durable jobs, failure preservation and stale-version rejection.
- [x] Locate current report text in source lines/fragments; edits invalidate automatic matches.
- [x] Confirm current report before export; selective excerpts and full sources are separate opt-ins.
- [x] Controlled CSV experiment with actual execution and reproducible script.
- [x] Preserve model failures and report semantic limitations; no general accuracy claim.

Mechanical verification and recording receipts belong to the delivery record. Implementation completion does not imply model completeness or human acceptance.

## Participant and publication gates
- [ ] Participant has reviewed scope/PRD/spec and the running product.
- [ ] Participant-authored personal reflection accurately describes their own contribution and learning.
- [ ] Any required exit survey is completed by the participant.
- [ ] Approved source is published in a public repository with license/run instructions.
- [ ] Actual demo is uploaded to YouTube or Vimeo and the link is verified.
- [ ] Final Devpost fields/links are reviewed, submitted and official receipt is reread.

No interview, personal learning completion or final submission is claimed by agent tests. Earlier draft checklists and failed evidence remain in the private history.
